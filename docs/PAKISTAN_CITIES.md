# Pakistan profile city selector

Personal information has one searchable **City** dropdown covering **117,579 populated places**. Both browsing and search results are alphabetical, with a visible match count and **Previous / Next** controls for every 60 results. The earlier population-ranked first-60 shortlist made the catalogue appear much smaller; the underlying catalogue has not been reduced or replaced. Search accepts English spellings and available Arabic-script aliases, shows province/territory labels within each option and works with keyboard or touch. There are no additional province/district form fields.

Selecting a result changes only the profile draft; **Save profile** persists it. A search that is not selected does not overwrite the current city. Cancel discards the draft. An older saved city string remains intact even if the catalogue does not contain it, and **Clear city** explicitly removes the optional value. The search field has one rounded outer border; its inner text input stays transparent and borderless even when the app's general field styles load later.

The source is a broad populated-place gazetteer, **not a guaranteed complete official list of every legally designated Pakistani city**. Cities, towns and villages are included so smaller hometowns remain selectable. This city is a coarse profile label, not a geocoded position, a routing restriction or a request to collect GPS. Duplicate place names are qualified by province/territory in the dropdown; the existing profile API still saves the city name as a string. A legacy name-only value marks at most the highest-ranked matching record as selected. An explicitly chosen regional row stays selected within the open edit draft; the region is not separately persisted or inferred as a verified user location.

## Performance and interaction

The catalogue is a dynamic-import chunk requested only when the City dropdown opens, keeping the initial map path independent of this data. Successful data/index loading is cached for the page session; failures are explicit and reopening retries. Search strings are normalised once while loading. An alphabetical reference index is sorted once per loaded catalogue; the latest normalised query's matches are reused while paging. Typing a new query searches the full catalogue and returns to its first page. Empty-query browsing and every search use the same A–Z ordering; name prefixes no longer jump ahead of alphabetically earlier matches.

Only **60 option rows** are rendered at a time, including when browsing the final page of the catalogue. **Previous / Next** replaces that page rather than continually appending thousands of DOM nodes. The count and current range stay visible. Search is the practical way to reach a specific city in this broad gazetteer; paging remains available without a hidden maximum-result cutoff. The data transfer and first local index creation still have a cost on first opening, rather than being part of initial map loading.

The list is in normal document flow within the settings panel, with its own bounded scroll area, so it cannot extend outside the modal and become clipped. The search keeps focus while choosing results. Arrows move between options and cross page boundaries; Home/End moves within the current page and Page Up/Page Down switches pages. Enter selects the active result. The paging controls are also reachable with Tab, and activating one returns focus to the search without selecting a city. Leaving the complete picker cancels an unselected search. The first Escape closes the list and restores input focus, including when focus was on a paging control or source link; a subsequent Escape dismisses settings. Options expose their position and total match count to assistive technology. Buttons retain visible focus indicators, touch targets and RTL direction. Loading never starts location access, geocoding, trip collection or a server profile write.

## Refresh and validation

To refresh intentionally, download a new public `PK.zip` to ignored local tools and run:

```powershell
python scripts/import-pakistan-cities.py .local-tools/pakistan-geonames.zip
```

The importer is offline: it reads that ZIP and prints count, size and archive checksum. Review the data diff and update this dated provenance/count before committing. There is no automatic background place-data refresh.

`tests/pakistan-city-select.test.tsx` covers lazy loading, pointer/keyboard selection, draft preservation, explicit clear, aliases, province qualifiers, alphabetical bounded paging, full keyboard traversal, retry, one-border CSS against the global styles and modal Escape behavior from the input, paging controls and source link. `tests/pakistan-city-data.test.ts` checks real major-city coverage/aliases/region labels, the **117,579**-record count and alphabetical/final-page access. Existing profile tests retain Save/Cancel, polling and UID isolation coverage. Current integrated checks and browser evidence are recorded in [implementation status](IMPLEMENTATION_STATUS.md).
