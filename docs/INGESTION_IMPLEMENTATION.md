## What runs

1. `collectPublicPosts()` reads the fixed `https://x.com/shaheryarhassan` public page using ordinary HTTPS. It sends no cookies, credentials or browser session and executes no page scripts. There is no browser dependency or automated fallback to another source.
2. parse5 reads at most 2 MB per response and 35 top-level articles. Both classic `tweetText`/`time` markup and the observed server-rendered text containers/formatter JSON are supported. Timestamp formatter payloads are parsed as data, bound to the matching link/target ID and never evaluated as JavaScript. Foreign authors, quoted articles, invalid/conflicting timestamps and unsupported media URLs are rejected.
3. The profile provides candidate IDs and times. Up to four recent canonical detail pages establish full text and timestamp meaning. Known original times use `publishedAt`; edited-only details keep it null and store `sourceTimestamp: {at, kind: 'edited'}`. Ambiguous profile-only times are not queued. A previously established publication time survives later edit-only observations in both storage adapters.
4. A collection has a 35-second total deadline and 15-second request deadlines. Redirects and 401/403/429 stop collection; there is no login, challenge handling, user-agent impersonation, alternate domain or private API request. Failed detail checks cannot invent missing publication dates. Results always disclose partial coverage.
5. Eligible evidence is normally from the preceding 24 hours. Older known-publication posts up to seven days can remain candidates when their text contains an explicit date/future hint. Unknown-publication evidence is more conservative, and old pinned posts do not displace the four recent detail checks. These hints do not establish an active closure.
6. Canonical IDs and normalized content hashes deduplicate notices. Changed evidence creates a version and supersedes its old pending-agent job transactionally. Original, displayed/edit and retrieval timestamps remain distinct. References to bounded public media can be retained, but no image download, OCR or model inference happens here.
7. Source timing now uses a five-minute persisted deadline. Standalone's local scheduler checks due work every 30 seconds; production uses the private authenticated Cloud Run worker and external Scheduler. A 180-second durable lease and request coalescing prevent overlap. API production mode starts no polling timer. See [source deployment](SOURCE_DEPLOYMENT.md) for setup and [current status](IMPLEMENTATION_STATUS.md) for actual activation evidence.
8. Source coverage records observed counts, eligible changes/skips and the highest observed ID without claiming a complete cursor/history. Last success requires eligible accepted evidence. Source runs remain bounded to 100 summaries; notice history remains durable.

The public preview can miss bursts, older edits/deletions, truncated text and events while offline. A failed check is never evidence of no closures. No map restriction is created by collecting a notice.

## Manual fallback and agent handoff

Use the app's manual-notice form or `POST /api/notices` to paste a public advisory with an optional source link and original timestamp. The server stores the URL as evidence and does not fetch arbitrary URLs. Reusing a URL updates that notice's revision when the submitted content changes. Without a URL, an identical text/timestamp pair deduplicates by content hash.

The same durable queue is available at `GET /api/agent/outbox`. After handling a notice, use `PATCH /api/notices/:id` with `reviewed` or `dismissed`; use `pending_agent` to reopen it. Only the newest revision remains pending. For the first agent integration, use one worker and recheck notice revision immediately before publishing. This endpoint does not yet implement worker claims, leases, exactly-once execution, extraction output schemas, or automatic rollback of closures created from earlier notice revisions.

Before any extracted closure can affect routes, the future integration should validate a structured result, resolve time in Islamabad, map a bounded road segment, handle uncertainty and conflicts, and explicitly create a draft or a reviewed published closure through the API. Keep original notice provenance. A prompt alone is insufficient to guarantee those checks. The current manual closure editor and saved-journey logic work when automatic source collection is unavailable.

## Local operation

- Start the full app with `npm run dev`; the API stores `data/manzil.sqlite` plus its WAL/SHM files. `MANZIL_DATA_DIR` or `MANZIL_DB_PATH` can change the location.
- Run one explicit collection with `npm run source:check`. It prints status/counts, never complete raw post bodies or personal phone data. A nonzero exit means the source was blocked or failed; the database and manual workflow remain usable.
- `X_SCRAPER_ENABLED=false` sets the initial state for a new database; the UI's source setting is persisted afterward. The implemented profile and five-minute interval are fixed; changing `X_PROFILE_URL` or `X_POLL_MINUTES` does not retarget or accelerate collection.
- Do not commit local databases, source archives or `.env`. Standalone mode is trusted single-user SQLite; Firebase modes enforce token/admin checks and private UID records. The core is deployed, but this collector repair is local and no private source Scheduler is active.

For a read-only access test, run:

```powershell
npm.cmd run source:probe
```

This command does not bootstrap local/cloud storage or persist settings/notices. It reports public IDs, known/unknown publication times, source timestamp kind, text/media counts and status, never full post bodies. Exit code 2 means blocked/error or no eligible posts, rather than a successful empty city feed. `source:check` is different: it deliberately writes the normal intake queue to the selected non-production database.

The collector no longer needs Chrome, Edge, Chromium, Playwright browser downloads or `BROWSER_EXECUTABLE_PATH`. Existing private environment values can remain but are unused by this collector. Installing a browser will not resolve blocked HTTPS or changed source markup.

### Optional local image inspection

```powershell
npm.cmd run source:probe -- --download-images
```

This explicitly downloads images referenced by the accepted recent posts into a unique folder under **`data/source-probes/`**, which is excluded from Git and container uploads. Plain `source:probe` still downloads no images. The output gives `downloadDirectory` and each saved filename. Open those images locally; `manifest.json` associates them with source post IDs/URLs, original media URLs, byte counts, MIME types and SHA-256 hashes. Files remain local until deliberately removed. No app database, model, account or map data is changed; `applicationDataWritten: false` does not mean that this optional mode writes no local files (`localFilesWritten` reports that separately).

Only the exact public HTTPS `pbs.twimg.com` media/thumbnail paths are accepted. Up to eight distinct images are attempted per run, at most 5 MB each, with 15-second request and 45-second batch deadlines. MIME/signature checks accept JPEG, PNG, WebP and GIF; they do not fully decode or certify image contents. Redirects, credentials, SVG and non-image responses are rejected; access denial/rate limiting stops further downloads. Failed/skipped image attempts are explicit and produce exit code 2 without discarding collected text metadata. `elapsedSeconds` measures collection and `totalElapsedSeconds` includes optional downloads.

Photo versus video-thumbnail references are labelled in the output. A thumbnail is not the full video. Manual review can assess apparent relevance, but an image alone cannot establish road identity, capture time or an active closure. Gemini/OCR, automatic classification, full video handling, cloud storage and scheduled downloads remain unimplemented. At **14:26 UTC on 17 October**, live verification downloaded and visually inspected a **23,860-byte WebP video thumbnail** showing a vehicle beside concrete road barriers; this is potentially relevant evidence, not a verified closure/location. The same collection retained three posts when a fourth detail request timed out.

## Honest limitations to demonstrate

The public HTML can change without notice; text can be truncated, older or fast-arriving posts missed, and a publication can disappear between checks. Date hints are not semantic extraction. Images and video may contain essential route information that this version cannot interpret automatically; downloaded photos/thumbnails remain unclassified evidence. Five-minute polling adds detection latency even when access works. There is no assurance of recovering events while offline. Show source freshness and an explicit coverage warning in the demo, keep a manual import path, and never label a stale or unobserved feed as fully live.
