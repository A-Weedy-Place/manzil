# Manzil: clearer maps, routes and personal journeys

This records the initial redesign and its verification at that stage. Later owner-approved changes are documented in [bilingual navigation](BILINGUAL_NAVIGATION_AND_CLOUD.md) and [development accounts/tour](DEV_ACCOUNTS_AND_TOUR.md): Closures is a primary tab for everyone, Activity appears after sign-in, street-detour/demo/block-point controls are directly visible, and the map always shows Add restriction. Guests receive the skippable tutorial every fresh visit and after sign-out; signed-in users retain remembered first-use behavior. Automatic foreground rerouting and optional server-side Cloud speech now supersede the navigation limitations below. The [implementation status](IMPLEMENTATION_STATUS.md) records the latest 149-test/build result; earlier counts and browser checks below remain historical evidence.

**Colour refinement:** the owner found the first grey design too dull. Streets (colourful Liberty) is now the default, with five independently selectable basemap palettes. See [Map styles](MAP_STYLES.md) for current controls and colours.

## What changed

1. **Cleaner map:** a flat OpenFreeMap vector basemap rendered by MapLibre, with nonessential POIs/buildings removed in Clean mode. Larger controls; light, dark and system themes.
2. **Clear route choices:** up to three genuinely different routes for the same departure, drawn together in blue. Select a route on the map or in its card. Each has duration, distance and estimated arrival. Earlier/later departures have a separate expandable comparison.
3. **Visible closures:** bright red outlines, red shading and closed-road markers. Scheduled restrictions use dashed outlines. Saved restrictions change the actual routing search.
4. **Simpler controls:** Map, Closures, Saved, Activity, Profile. Source updates are under Profile → Source updates & collector; alerts remain in the top bell. On phones, expand/collapse controls with the sheet handle button.
5. **Personal preferences:** persistent local name/profile, theme, map detail, browser-alert preference and separate consent for learning usual journeys. This is not cloud account authentication.
6. **Advance warnings:** saved commutes are checked automatically. With separate consent, repeated recorded journeys can generate closure alerts without manually saving every route.
7. **Navigation:** route-step preview, optional foreground GPS guidance, voice prompts and fresh-position recalculation. Guidance is separate from trip-history recording.

Run `npm ci`, then `npm run dev`; open http://127.0.0.1:5173/. No deployment, Gemini or paid mapping credentials were added.

## Map and interface decisions

The owner's Android Safar screenshot names **MapLibre Android, OpenFreeMap, OpenMapTiles and OpenStreetMap**. This differs from the separately researched Safar website's Leaflet/CARTO stack. Manzil uses **MapLibre GL JS 6.14.0** with OpenFreeMap Liberty/Bright/Positron/Dark bases and selectable palettes. Provider instructions: [OpenFreeMap quick start](https://openfreemap.org/quick_start/), [MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/).

`src/lib/mapStyle.ts` copies the upstream style before removing 3D terrain/extrusions, POI/building detail and minor-road labels at lower zooms. Clean mode removes fill textures. Dark roads/labels have higher contrast. Detailed mode restores more labels. Attribution is retained from the tile source. Provider/network availability is independent of local routing; no synthetic basemap or route is invented on failure.

The renderer uses pitch zero, no rotation/3D, two workers, capped pixel ratio (1.75), limited tile-cache zoom levels and reduced-motion support. Map code loads separately from the app shell. The tested production build has approximately **323 kB shell JS / 100 kB gzip**, **1,068 kB map JS / 293 kB gzip**, a **506 kB worker**, and **137 kB CSS / 22 kB gzip**. This is a larger download than the original Leaflet version. Low-end device profiling and production load remain untested; no lower-GPU-use claim is made.

Route labels are repositioned after viewport moves and avoid one another where space allows. Alternatives remain muted blue; the selected line is saturated blue with white casing. Closure markers remain visible when their polygon is smaller than a screen pixel. Coordinates remain GeoJSON `[longitude, latitude]`; entered latitude/longitude and schedules follow the existing editor/PKT conventions.

The journey form collapses after planning so route choices appear first. A Leave now search uses the actual search time rather than an old form timestamp. An explicitly entered departure remains scheduled. Reopen the journey-summary row to edit endpoints/time. Unsaved work and calculated plans remain memory state.

## Real alternatives

The router uses bounded corridor exclusion/penalty searches for distinct connected paths. Search-only penalties never inflate travel duration. Every candidate is revalidated against access, direction, mapped turn restrictions and closure traversal times. Diversity/usefulness limits reject minor parallel-road changes and excessive loops. A shared computation/search budget bounds work; fewer than three useful choices may exist. See [ROUTING.md](ROUTING.md) for thresholds and tests.

Times use road speeds and junction allowances **without live traffic**. They cannot match Google's traffic-aware ETA quality. Historical departures remain marked as replay. Future event ends imply an announced reopening assumption, not field confirmation.

## Profiles and usual-journey alerts

`GET/PATCH /api/profile` persists `displayName`, `theme`, `mapDetail`, `browserNotifications`, `inferFrequentRoutes` and car transport in SQLite. Profile responses appear in `/api/state`. IDs/timestamps are server controlled. Multiple browsers pointing at this single-user local server share that profile/data; no login screen implies nonexistent account isolation.

**Learn my usual journeys** explicitly enables local inference and alerts from saved GPS history. It is off by default and separate from history-recording and road-discovery contribution consent. Requirements include three matching trips on three independent PKT dates, enough good fixes/reliable travel, similar directional endpoints and a similar departure window. Poor accuracy, gaps, implausible movement and insufficient samples are excluded. A bounded recent set of retained trips produces summary proposals through `/api/frequent-routes`, without raw traces. Exact thresholds: [API.md](API.md).

An inferred journey represents likely endpoints/time, not proof of repeating an exact historical path. Its next occurrence is planned over the current graph and checked against closures. Learning does not publish roads, label home/work or silently save a commute. Proposals can explicitly be saved. Duplicate warnings are suppressed only when a matching saved journey's computed plan includes the same disruption. Opting out stops inferred checks and hides proposals; it does not delete history, explicit commutes or existing alerts.

Saved/inferred alerts stay in the durable inbox. Browser notifications require an explicit setting and browser permission. Only genuinely new, recent, unread alerts are eligible; loading the app or opting in does not replay the inbox. Delivery rechecks consent after asynchronous worker setup, deduplicates IDs and groups bursts.

`public/notifications-sw.js` displays notifications and focuses the inbox when clicked. It has no push subscription/background polling. The page must remain open and backend running; browser/OS restrictions can prevent delivery. Mobile may require an installed app. No closed-app push is promised. Enabling it allows journey details in the OS notification area. [Notifications API guidance](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API).

## Foreground navigation

Select **Preview & navigate**. Preview includes step selection, next/previous, remaining distance/time and a map point. Preview points are guidance points, not GPS observations.

**Start GPS guidance** requests fresh high-accuracy location. The first accepted fix triggers a route at the current time from the actual position. Prompts/ETA pause until a fresh valid route returns. Accuracy/timestamp checks reject unsuitable fixes; route matching limits implausible jumps at loops. Guidance samples stay in memory rather than entering personal trip history.

The geometry guide estimates bearings, road transitions and progress. Optional speech uses browser voices; pronunciation varies. There is no lane guidance, signposted exit dataset, live traffic or certified navigation instruction source. **Near the destination road point** requires fresh GPS/accuracy/proximity checks and is not proof of reaching an entrance.

Failed refreshes cannot resume old directions on the next fix. Restriction revisions, stale GPS, hiding/leaving the view and Stop invalidate guidance and cancel speech. Off-route detection offers **Recalculate from here** when safely stopped. Background operation, screen-off GPS and automatic off-route rerouting are not implemented. Temporal closure exposure is checked at planning/replanning, rather than continuously resimulated against actual travel delays. [Geolocation documentation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/watchPosition).
