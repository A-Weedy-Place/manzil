## Contributor and agent behavior

- Select two ends on a road to close its connected interval, or draw/tap a short transverse blockade. Preview helpers load missing road data automatically; no city switch is required.
- The first uncached request may take longer. The editor shows **Selecting road…**, remains cancellable and has a 25-second hard deadline. A late response cannot overwrite a new drawing, type, account or closed editor.
- Public geometry previews save nothing. Ordinary contributions still require sign-in and remain private pending review. Verified contributors/admins retain the existing publication/review permissions. Blockades are revalidated against available mapped roads on creation, editing and approval, including agent drafts.
- Selected typed road/barrier lines render in full across the old offline graph edge, including when the bundled graph is unavailable. Public status, moderation and selected-time checks still control red/yellow visibility. Road intervals beyond that offline graph retain `unverifiedDrawing: true`: the type alone is not persisted proof that a direct API client used the road picker. Inside coverage, road intervals still clip against actual graph roads. A validated blockade retains its transverse line. An untyped legacy outside drawing also remains explicitly marked; its appearance does not certify road matching.
- Gemini location preparation no longer accepts only Islamabad by name. It resolves the supplied city, named road and source endpoint/point references before acquiring the corresponding graph. Exact road/intersection matching and ambiguity checks remain. A similarly named road in another city cannot be substituted silently. Source/Gemini schedules, model calls, review requirements and deployment are unchanged.

API bodies remain GeoJSON `[longitude, latitude]`: `/api/roads/point` accepts `{coordinate}`, and `/api/roads/section` / `/api/roads/blockade` accept `{from,to}`. Successful responses remain `{drawing,roadNames,distanceMeters}`. Unsupported selections return **422**; unavailable/rate-limited/failed road data returns **503** with retry guidance, without inventing a connecting line or publishing a report.

## Source, topology and lightweight caching

`RoadCoverageProvider` uses the fixed server-owned HTTPS **Private.coffee Overpass** endpoint first. A bounded query requests highway ways in the selected neighbourhood, their parent turn restrictions and recursively referenced ways/nodes. If it fails, a small single bounding box can use the official read-only **OpenStreetMap `map.json`** API. The fallback is limited to **0.0025 square degrees**, one request at a time and at least one second between starts; broad/dateline-spanning areas do not use it. This is a lightweight editor fallback, not a bulk downloader. No authentication or OSM editing/upload operation is used. Custom Overpass endpoints disable this fallback unless explicitly configured by the server.

Both sources use OSM node references to build topology, with the same public car-access, barrier, one-way and conditional-access filtering as the bundled graph. Visual crossings are not invented junctions. A road-closure selection is a geometric interval, rather than a legal driving itinerary; routing separately enforces direction/turn constraints. Extra source contributor metadata is discarded by graph construction. The official map API does not supply a uniform database-snapshot timestamp, so that graph carries an explicitly unknown source time rather than presenting retrieval time as source freshness.

The neighbourhood expands about **500 m** beyond selected points and rounds outward to a stable **0.005° longitude/latitude** grid (longitude padding accounts for latitude). Nearby picks reuse a cached area. At most **12 areas** / **300,000 total node+edge units** are retained for **20 minutes**, in memory only; identical concurrent requests share work. There are at most **two** distinct outstanding requests. Source failures back off briefly; HTTP 429/406 causes a **30-second** endpoint cooldown. The source body is limited to **4 MiB**, **60,000 elements**, **150,000 references** and **200,000 graph edges**. Invalid/incomplete topology or runtime-error responses are rejected. An **18-second** total deadline and **8-second** attempt deadlines cover fetch and body reads, even if a test transport ignores cancellation; late results do not enter the cache.

No country/city polygon is consulted by this road-coverage provider. Valid global coordinates are accepted subject to mapped data and bounded work; it is not a worldwide offline database. The existing application driving search/planner remains scoped to Pakistan, already supporting other cities through its online provider. The Local bus dataset remains Islamabad/Rawalpindi, and the weather feed remains explicitly labelled Islamabad.

Picked coordinates and the surrounding public-road area are sent from the API to the selected Overpass/map-data provider. Account identity, photos and stored GPS traces are not sent with that road query. The in-app Privacy Policy discloses these requests. No API key or paid activation is required for these public endpoints. Public servers have limited capacity and availability; this small localhost prototype is not a production service-level promise.

## Retained limits

Removing the city gate does not remove validation/resource bounds. Road sections are **3 m–6 km**, at most **400 output vertices**, with both picks within **45 m** of supported connected same-road geometry. Blockades are **2–80 m**, two points and a **4 m** footprint; road intervals use **14 m**. A whole long motorway still needs manageable separate sections. Private/inaccessible roads, absent mapping and unsupported conditions remain unavailable. Graphs model road/carriageway centerlines rather than individual lanes; two-dimensional closure footprints can conservatively affect overlapping flyovers. The external routing adapter validates returned candidates against actual closure polygons/times, but does not promise arbitrary polygon-avoiding detours when its provider returns no valid alternative.

Deterministic tests use synthetic public-road fixtures in multiple cities and abroad without inserting runtime fake roads. They cover caching/deduplication, bounded transport, topology/access, outside-area previews, moderation/privacy, typed-line display/time and revision conflicts during asynchronous approval.
