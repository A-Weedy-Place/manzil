# Accounts and profile — 18 October

These changes are localhost work on `codex/feature-development`. The core app already has a Firebase deployment; publishing this feature branch does not release these screens or activate cloud scheduling. The deployment developer handles integration and release. No local database, GPS history or credentials are migrated.

## Using the screens

**Policies (18 October):** guests and signed-in users can open **Terms & Conditions** and **Privacy Policy** from Profile. Both use the same adjacent/phone settings panel, with English/Urdu text, document tabs, a dated header and source/provider links. Opening or switching them does not accept terms, collect GPS or change consent. X, Escape, repeating the selected row and outside clicks dismiss them. The text describes actual controls and data flows, including provider requests, 30/90-day trip retention and the absence of self-service account deletion; it does not invent a support identity/contact or promise legal compliance. [Policy content/evidence and tests](LEGAL_AND_PRIVACY.md).

The right-hand map is a lightweight static illustration of a closed road and a detour, not a live closure feed. The matte-green backdrop has original white country-outline/road-scan, travelling-pin detour and detailed roadside bus/walker/sign scenes, with a small card shadow, desktop pause/play, hidden-tab pause and static phone/reduced-motion scenery. Narrow screens prioritize the form. Automatic onboarding follows registration or explicit guest entry only; ordinary login and resumed guest reload skip it. Local registration/reset lifecycle is tested; production inbox delivery is a separate check. [Artwork/auth evidence and limits](ENTRY_SCREEN.md), [tour behavior](DEV_ACCOUNTS_AND_TOUR.md).

## Fuel prices and period statistics

The Fuel prices panel shows the latest applicable dated petrol/diesel reference, effective date, source link, last check and cached/unavailable state. The free public [PSO POL archive](https://psopk.com/fuel-prices/pol/archives) supplies the existing collector; [PSO's fuel-price page](https://psopk.com/en/fuels/fuel-prices) links its price information. No social-media subscription or Champ extraction is needed for this source.

The running local worker checks **once per Pakistan date**. A daily check does not mean prices change every day. Published effective dates are kept separately from retrieval dates; PSO reference prices exclude outlet freight. There is no assumed government JSON API or hardcoded live price. Production scheduling remains separate release work. See [fuel contracts and coverage](FUEL_COSTS.md).

Vehicle type, optional name, petrol/diesel and user-entered **km/litre** are private preferences. Saving them does not grant GPS consent. Routes retain the car-road access/time model even for motorcycle fuel estimates. Recorded trips keep immutable vehicle/rate snapshots; unknown or uncovered periods remain unpriced. Both weekly and monthly totals identify missing prices and partial retained-history coverage.

Periods use each completed trip's **departure date in Asia/Karachi**: the week begins Monday, the month begins on its first day, and daily bars run through today. A trip crossing midnight is grouped by departure; it is not split across days. Quiet calendar days have zero values. Distance includes all retained completed trips; fuel totals include only trips carrying a saved estimate, so a zero fuel bar does not establish that no fuel was consumed. The information control explains this distinction. Charts use private coordinate-free daily aggregates, not a new request for raw traces. An older API without a daily series shows **Daily chart unavailable** instead of inventing a distribution from an overall total.

## Developer boundaries

- `AccountPanel` uses the existing accessible modal/focus handling. `public/manzil-route-preview.svg` is repo-native illustrative artwork, with no map/network dependency. Development-account shortcuts stay collapsed and localhost-development-only; normal screens omit emulator implementation notices.
- Profile editing stages photo/name/location locally. Photo processing retains image validation/re-encoding and account-change guards; a late result for another UID cannot become the current draft. Form errors keep the draft available for retry.
- `ProfileSettingsDialog` is the shared accessible wrapper. Outside dismissal is opt-in here; account, consent and tour dialogs retain their own existing behavior. The parent controls one open section at a time; view/UID changes clear it. App snapshots are exposed only to their matching account. Late panel errors/photo results do not leak into another opened section. Guest settings retain only appearance/language and public fuel prices.
- `TripHistory` is shared with Activity, without any GPS watcher. View/Share/Save journey explicitly load one authorized detail and retain UID/late-response guards. A chosen historical path takes display precedence without becoming a freshly validated navigation route. A temporary map/image exists only within the guarded Share flow; closing or changing UID aborts work, removes it and revokes its URL. Summary-only history remains unavailable for trace actions. The guarded local User 123 seed supplies simulated public-road coordinates; PNGs label simulation and GeoJSON retains `simulated:true` with explicit fictional/public-OSM provenance. These coordinates were never captured from a device, and no private GPS file is committed or implicitly migrated. Seed upgrades preserve edited/deleted records and consent rather than resetting the account.
- `MonthlyStatistics` retains its component name but now offers both week and month views from `GET /api/trips/statistics`, with loading, timeout, retry and partial/unpriced states. Opening the dialog never starts a GPS watcher, requests browser location or loads raw trip traces. Activity reuses the same period tabs/charts. Backend `week`, `month` and `all` totals remain available; week/month also include daily aggregate series. The chart has an accessible title/description and an expandable value table, so exact amounts are available without pointer hover or interpreting bar height.
- Optional `LocalProfile.travelDataChoiceMade` records acknowledgement, **not collection consent**. Only successful registration marks that UID pending in memory/session storage; the API stores the acknowledged choice. Allow sets collection and inference true; Not now sets both false. Dismissing the consent dialog follows Not now. Failed writes remain retryable and do not claim the preference changed. See [personal-data lifecycle](PERSONAL_TRAVEL_DATA.md) and [API](API.md).
- Route, closure/time/access validation, private UID storage, explicit unavailable states and retention rules are unchanged. Gemini, cloud speech activation, background GPS and reliable closed-app push are not activated by these UI changes.

Automated verification covers shared-panel behavior, staged photo Save/Cancel, late-photo UID isolation, permission toggles, the curated alphabetical city list/aliases/legacy values, weekly/monthly and daily retained-history totals, unavailable/partial totals, explicit history actions and no extra GPS watcher. Final integrated counts and actual browser/GPS evidence belong in [implementation status](IMPLEMENTATION_STATUS.md); successful simulated coordinates do not verify a physical device's location accuracy.
